# Shards

Самостоятельный магазин скинов CS2, Steam-пополнений и подарочных карт Apple. Структура актуального Flare, визуальные источники — Spectra Lab и Butter. Название проекта и внутренняя валюта — Shards.

## Запуск

Node.js 24, npm.

```sh
npm ci
npm run dev
```

Локальный preview: http://127.0.0.1:5198 . Другие проекты используют другие порты.

```sh
npm test
npm run lint
npm run typecheck
npm run build
npm run start:local
```

Статический экспорт: `npm run build:pages`; корневой путь задаётся `SHARDS_PAGES_BASE_PATH`. Экспорт блокирует серверные финансовые сценарии и хранит корзину только на устройстве.

## Реализовано

- Главная, каталог, 68 страниц товаров, quick view, корзина, кабинет.
- Поиск, категория, состояние, цена, StatTrak, сортировка, избранное на устройстве.
- Сравнение пары покрытий по цене, float, состоянию.
- Новый Duo: нож + перчатки, общий бюджет, остаток/превышение, атомарное добавление без дублей.
- Steam слева и баланс справа после hero; конвертер перед FAQ.
- Apple: регион, номинал, подтверждение соответствия Apple Account, сброс подтверждения при смене региона.
- Нижнее подтверждение добавления работает и внутри native dialog. После добавления — ссылка в корзину на всех поверхностях.
- Корзина/избранное сохраняются; при запрете записи localStorage работает резерв текущей сессии.
- Hero, глянцевые функциональные значки, появления по прокрутке, реактивный многослойный footer, reduced-motion.

## Границы

Каталог — датированный снимок из предыдущего проекта с сохранёнными source-полями; это не подтверждение текущего наличия и цен. Курс подтверждён владельцем: 1 ₽ = 1,6 Shards (1 Shard = 0,625 ₽). Цены каталога пересчитаны в Shards с сохранением прежней рублёвой стоимости. Steam 5% остаётся условием прототипа.

Steam profile lookup проверяет только публичный профиль, не право на пополнение, не авторизацию. Кабинет — локальное представление; Steam OpenID не подключён. Checkout и пополнения не создают заказ/платёж/баланс. Apple не выдаёт цену в рублях или код без поставщика. Регион/номинал — интерфейсные примеры.

Для коммерческого запуска нужны договоры/доступы провайдеров, серверная авторизация, каталог и выдача, ledger/idempotency, webhooks, юридические сведения. Не хранить секреты в клиентских переменных. Для домена задать APP_ORIGIN.
