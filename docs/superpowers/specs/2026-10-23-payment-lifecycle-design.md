# Новые платежи и продолжение оплаты

Основание: исследование полного flow и разрешение пользователя «давай исправим» от 23.10.2026.

Форма создаёт новый платёж независимо от предыдущих неоплаченных. Повтор неизвестного HTTP-результата сохраняет исходные key/body. История и страница платежа имеют отдельное действие «Оплатить», которое сначала проверяет конкретную операцию у провайдера. Оплаченный, истёкший или непроверенный платёж не открывает старую форму.

## Подход

Используем существующие PaymentsService, ownership/guest access и reconciliation, добавив адресную проверку. Отдельный worker или опрос провайдера на каждом GET не нужны: первый дублирует инфраструктуру, второй превращает чтение истории в массовые внешние запросы. Проверка по кнопке — POST с CSRF; обычное обновление истории читает БД.

Срок формы Arco Pay — 900 секунд, сохраняется при создании; миграция заполняет срок старых Arco Pay платежей. `EXPIRED` хранится как failed с причиной expired, отдельно отображаемой пользователю. По времени одному оплата не отвергается. Не подтверждённые операции через 5 минут после конца срока переходят в manual_review и продолжают сверяться. Неизвестный CREATE без provider ID сохраняет существующий recovery. Поздний CHARGED/IPS_ACCEPTED зачисляется ровно один раз; Steam не меняет Shards wallet.

История и status API возвращают expiresAt, failureReason и canPay. Только успешная адресная проверка может разрешить переход на checkout. Пользователь видит истечение, ожидание подтверждения или ошибку проверки. Фоновые проверки и метрики охватывают просроченные неопределённые платежи.

Сохраняем композицию, стили и responsive; используем существующие кнопки/сообщения. Существующие флаги активации не меняются. Работа в данном checkout, без production изменений, реальных платежей, push и deploy.

## Проверки

Новый платёж при старом pending, reload/изменение суммы, точное восстановление неизвестного запроса, ownership и CSRF для customer/guest, проверка pending/paid/expired/error перед redirect, недопустимые provider состояния, закрытие expired фоном, overdue→review→поздний paid, гонка callback/check без дубля ledger/fulfillment. Node 24; DB только локальная shards_test пользователя shards_test.
