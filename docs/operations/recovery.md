# Восстановление и наблюдаемость

Новый checkout сначала удерживает Shards. До terminal supplier result это не paid/delivered. Каждая линия хранит неизменные цену, cost cap, получателя и provider_operation_id; смена текущего trade-URL не меняет принятый заказ.

При timeout создания SIH искать заказ только по исходному provider_operation_id. Не создавать новый supplier order. До dispatch восстановленный lease возвращает pending; после dispatch — awaiting_confirmation и только GET. Неизвестный результат pay Steam уходит в manual_review с исходным transaction ID; повторный pay и автоматическое зачисление Shards запрещены. Admin reconciliation — авторизованное, идемпотентное действие с обязательной причиной и audit. Если провайдер не даёт подтверждаемого read/resolution контракта, ручное решение требует сверки с ним и отдельного аудируемого разрешения; общего «считать доставленным» API нет.

Sibling-линии сериализуют settlement: capture равен сумме действительно доставленных строк, остаток hold освобождается после всех terminal результатов. Неизвестные линии не освобождают hold. Sweep исправляет terminal orphan holds идемпотентно. Для остановки новых покупок/пополнений выключить SHARDS_CHECKOUT_ENABLED/SHARDS_PAYMENTS_ENABLED; для остановки новых submit — SHARDS_FULFILLMENT_ENABLED. Webhook, reconciliation, lookup и settlement оставлять работающими.

SMTP/VV outbox: lease 3 минуты, восстановление максимум 20 за цикл, monotonic attempt_count fencing; поздний ack старого worker не меняет состояние. VV отправляет неизменный eventId и соблюдает порядок одного subject. Повтор после remote acceptance обязан дедуплицироваться получателем по eventId. SMTP получает стабильный Message-ID; SMTP и Slack не гарантируют exactly-once, поэтому после потерянного ack уведомление может повториться. Это не повтор платежа/выдачи. OTP может быть повторно доставлен, но срок и single-use проверяются сервером.

Protected `/admin/integration/health/operations` отдаёт счётчики без credentials/получателей: orphan_holds >0, aged_unknown >0 (24ч), stalled_outbox >0 (15мин) требуют alert. catalog_age_seconds отсутствует или >900 — каталог устарел; stale позиции непокупаемы. Worker log silence >3 интервалов — alert системы сбора логов. Проверять процессы fulfillment, reconciliation, catalog, notifications и vv-admin отдельно от API health.

События VV v2: SHARDS — собственная строковая валюта, допускаемая текущим контрактом VV. order.created имеет payment.pending. Терминальный order.completed означает законченный settlement; VV не поддерживает отдельный partial enum, поэтому fulfillmentStatus=partially_fulfilled и статусы строк сохраняются в raw event. В интерфейсе Shards частичная выдача видна явно. manual_review не выдаётся за completed/refunded: есть audit, Slack событие и monitoring. Top-up paid не означает Steam delivered.

Backup: `pg_dump -Fc` собственной БД в зашифрованное хранилище с ограниченным доступом; отдельно хранить ключ шифрования и конфигурацию. Восстанавливать `pg_restore` только в новую БД/volume, сначала без workers и с false финансовыми флагами. Проверить число users/orders/payments/ledger/holds/quotes/commands, wallet reconcile, ключ расшифровки и provider IDs. Затем включить только lookup/reconciliation. Не запускать старый и восстановленный клон одновременно против одного провайдера. Репетиция на локальном shards_test описывается в acceptance-results.md; это не проверка production backup.
